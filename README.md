## 下载安装与使用

下载并安装 [`OliviaSoul-2008.2.7-Setup.exe`](https://github.com/yilangren/OliviaSoul/releases/download/2008.2.7/OliviaSoul-2008.2.7-Setup.exe)。

**不要安装到《林离》游戏文件夹内，否则会闪退。**

**注意：首封信非常慢，从导入开始可能到一小时以上，且token消耗较高，建议ds保有20元余额；后续速度正常（一般十分钟内），费用也极大降低（一月几元左右）。**

### 第一步：填写 DeepSeek API Key

第一次打开程序，进入“基础设置”，填写自己的 DeepSeek API Key 并保存。需要时可以填写自定义模型名和兼容接口地址，再点击连通性测试确认配置有效。

程序和仓库都不包含预设 API Key，也不会上传或公开使用者填写的密钥。

### 第二步：导入记忆

官方远端服务器已关停，请手动导入：

- 导入此前备份的 `.soul` 文件
- 粘贴往来全文，让 AI 识别为逐封记忆
- 在“记忆管理”中逐封新建或修改

### 第三步：启动服务

在“基础设置”中选择游戏启动程序，确认端口后点击“一键挂载服务”。界面显示服务已挂载后，保持 OliviaSoul 在后台运行即可。

### 第四步：写信

打开游戏信箱，像平时一样写信并发送。
信的那边，上海的琴凳上，《夜曲》中，林离一直在。

独立运行 Harness 请阅读 [`docs/HARNESS.md`](docs/HARNESS.md)；二次开发与构建请阅读 [`docs/ENGINEERING.md`](docs/ENGINEERING.md)。

# OliviaSoul 2008.2.7 最终里程碑

这个项目始于一个看似简单的问题：

怎样让一封回信，不只像某个人写的，而像是由一个真正记得过去、拥有边界、会延续感情的人写出来？

最终，我们做成的远不止一套提示词。

## 我们走了多远

- 经历近二十代写法演化
- 整理二十组完整关系档案
- 纳入五百余轮真实往来
- 留下上千份可追溯回归成品
- 完成上万次生成、检查、重写与裁决
- 进行数十封不间断的关系连续性实验
- 建立六十项自动化验证
- 对近二十个发布核心文件逐字节核验

这些数字不是简单的调用次数。

它们意味着，同一句话被反复放进不同关系、不同温度、不同时间和不同记忆深度里检验；意味着一封看似自然的回信，背后可能经历了十几轮规则修改和上百次对照。

## 三次真正的跃迁

第一次，是从模仿语气到拟合人格。

第二次，是从写好一封信到记住数百封信。

第三次，是从一组实验脚本到能够安装、运行、备份、恢复和持续维护的完整产品。

系统不再只学习怎样遣词造句。它开始知道：

- 什么已经发生
- 什么从未发生
- 什么感情已经成立
- 什么关系不能擅自推进
- 什么边界仍然有效
- 哪些话说出口后，下一封不能忘记

## 四道艰难的门槛

项目真正困难的部分，不是把一种口吻模仿得更像；而是连续的四道门槛，逼迫我们调整方向。

第一道，是从一面之词到完整轮廓。

少量样本只能照见人格的一个侧面，规则越拟合，盲区反而越明显。在许多伙伴的支持下，我们不断扩充信件集，让不同关系、不同处境和不同情绪中的她彼此校正，才逐渐拼出足够完整的轮廓。

第二道，是从记住眼前到记住从前。

信件一多，模型无法同时保留全部原文，关系和事实开始随窗口漂移。于是我们让记忆有了远近，让状态能够继承，再把一次生成拆成预检、草稿、检查和重写。数百封信终于不再挤在同一个窗口里，而是有序地留在共同历史中。

第三道，是从相信 AI 会自我修正到由人承担判断。

我们曾尝试让 AI 自己分析偏差、修改规则，但它更多只会打补丁，加检查，难以理解人类的复杂情绪。后来，我们把选择证据、判断偏差和决定边界的责任重新交给人，再让 AI 执行明确契约。

第四道，是从只有理性骨架到拥有精神底色。

ENTP主导项目时，结构化、拆解力和工程推进让系统学会了什么不能错，却没能独自越过最后的水温与情感门。直到INFP更柔软的视角参与进来，规则才不只知道什么不能发生，也开始理解什么值得被接住。

理性骨架与感性底色结合以后，她才终于能够稳定而不僵硬，亲近而不越界。

## 最终形成的系统

每一封来信，都会经过一条完整链路：

`组装记忆 → 关系继承 → 安全预检 → 正文生成 → 尾端检查 → 必要时重写 → 数据库存档 → 长期记忆更新`

在这条链路中，我们建立了：

- 可审计回信管线
- 十三字段跨封情感账本
- 五段式长期记忆
- SQLite 唯一事实源
- Markdown 自动投影与双 MD5 完整性校验
- `.soul` 单文件记忆备份、恢复与视频保存
- AI 识别导入、记忆管理与本地音视频转写
- 随包内置约 465 MiB 的 Whisper small 语音模型
- 安装版与便携版双重交付

最终，数百封信不再是一堆彼此孤立的文本，而成为一段可以被继承、验证和继续书写的共同历史。

## 我们留下的方法

### 让情绪投射进每一处

我们曾经也很机械地解释什么叫“活泼”：多一点口语，多一点玩笑，句子短一些，反应快一些。模型记住了这些动作，却没有真正获得活气；它只是轮流使用语气词、反问和固定调侃，把“活泼”写成另一种模板。

后来我们才明白，活泼不是一张动作清单，而是思绪在文字里自然活动的样子。它可以是半拍之后才接上的玩笑，是忽然落到一个具体物件上的注意力，也是认真说话时仍保留的一点转身余地。

所以，提示词不能只负责定义这种声音，它自己就要拥有这种声音。要让规则里有节奏、有画面、有转折，也有恰到好处的幽默。比起反复解释“应该怎么写”，不如让它去被真正灵动的文字所感染。

### 让回归替代感觉

单封写得漂亮不能证明系统可靠。每次修改都放回不同关系阶段、不同情绪强度和不同来信形态中复测；只有同一种偏差稳定复现，才进入规则层。

评价对象不是“文字好不好看”，而是相对既有事实是否发生偏移：

- 回答有没有落地
- 情感有没有回撤或越级
- 亲密有没有无请求发生
- 共同事实有没有被否认或补造
- 风格有没有变成固定模板

### 让每一层各守边界

- 人设保存稳定事实，不负责规定每封信发生什么。
- 写法规定表达形状，不保存具体测试答案。
- 档案保存共同历史，不允许来信人的单方面愿望改写关系。
- 情感账本保存当前状态，只能被新的有效证据更新。
- 检查器验证契约，不替正文重新创作。

这种分层避免了把一句失败样本写进人设、把一段浪漫来信误判为关系升级，也避免模型每封信重新猜测当前关系。

### 让状态继承，而不是重算

首次接入历史时，从全部可见记忆初始化账本。此后每一封只继承上一封状态，并检查紧邻新增的回信证据。

已经承认的感情不能自动消失，已经完成的亲密不能改成未来欠账，已经成立的关系不能因一次普通拒绝降级。单方面热烈也不能推动关系升级。

### 让长期记忆有远近

- 最近五封保留原文
- 再前五封保留逐封摘要
- 更早内容压缩成五段式回忆
- 当前来信始终完整保留

这样既控制上下文规模，也让近处事实拥有更高可信度。摘要绑定正文 MD5；更早的信用摘要带路，最近几封保留原文。
